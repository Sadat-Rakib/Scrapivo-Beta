## Architecture
USER → PROFILE/DEFAULTS (backfilled Memory; sidebar item renamed "Projects") → PROJECT (context_version, ICPs, Offer) → QUERY+CONTEXT RESOLVER (query > project > global; per-field provenance: explicit | project | global | inferred) → COMPILED THESIS → SEARCH JOB (context snapshot pinned at start, target/budgets, atomic lease) ← WATCH TRIGGER (creates the same SearchJob) → elastic discovery → normalized candidate reservoir → BASE ELIGIBILITY → adaptive research (HTTP-first / browser / signals) → FINAL QUALIFICATION → Opportunity Packets → SEARCH DATASET (the job itself) + curated LISTS → canonical fact write-back → Research Graph → future reuse.

## Data model
- `projects`, `project_context` (edits bump `context_version`), **`project_icps`** (id, project_id, name, definition jsonb, is_default, created_at, updated_at; `project_context.default_icp_id` references one). ICP = reusable target definition; saved search = particular compiled thesis. Distinct objects from day one.
- `search_jobs`: id, user_id, project_id, watch_id (nullable), **scheduled_for timestamptz nullable**, spec, target, mode interactive|batch|job|watch, status queued|running|paused|stopped|completed|failed, completion_reason TARGET_REACHED|COVERAGE_EXHAUSTED|BUDGET_EXHAUSTED|USER_STOPPED|FAILED, discovered/researched/qualified counts, current_pass, budgets, project_context_version + context_snapshot (job executes against the context it started with), lease_owner/lease_expires_at/heartbeat_at, pause_requested_at/stop_requested_at, error, timestamps. **UNIQUE(watch_id, scheduled_for)** on watch jobs — concurrent cron runs are deterministically safe.
- `search_job_candidates` (UNIQUE(job_id, candidate_key)), `search_job_queries` (UNIQUE(job_id, query_hash)), `search_job_sources` (cursors, exhausted flags, metrics).
- `watch_seen_matches` (watch_id, entity_id, match_fingerprint, first_seen_at) — NEW_ENTITY and NEW_SIGNAL change modes. Watches store compiled thesis/spec + project_context_version at creation; later project edits prompt "Update this Watch?" — never silently change meaning.
- `notification_connections` (server-only, encrypted credentials) + `notification_outbox` (idempotency_key, channel, **status pending|sending|delivered|delivery_unknown|failed**, attempts, timestamps).
- `source_yield_stats` (query_family, entity_type, source, attempts, candidates, qualified, contacts, signals, latency_ms, failures) with time-decay smoothing — five lucky results never permanently dominate routing.
- `project_lists` + `project_list_items` (reference canonical entity/packet ID + source job_id; no copied lead records).

## Workstreams

**WS1 — Durable Search Job engine + elastic widening (spine).** One engine, four triggers (user search / batch / job / watch-due). **Atomic lease invariant:** claim/reclaim via atomic UPDATE/RPC/transaction only — never SELECT-then-UPDATE — so exactly one worker transitions queued/expired → running + lease_owner + lease_expires_at. Heartbeat/update confirms ownership; lost lease → worker stops that job immediately. Child-table unique constraints are the second line of defense. Desired-state pause/stop honored at safe checkpoints after persisting progress; completion_reason set at terminal. Yield-math widening (deficit estimate → untried variants + growing pool + source cursors; never restarts, never re-researches). Mode-based deadlines (interactive 120s / batch 10m / job per-pass). Research Jobs first-class UI ("AI SaaS Founders — 742/1,000 — Running — started 2h ago"); "Project settings changed since this job started — apply to future research?" prompt on context drift.

**WS2 — Acquisition policy (HTTP-first) + browser reliability.** HTTP/JSON-LD first when the page is statically usable; browser only when rendering/navigation is needed. Browser-failure ladder: one retry → HTTP fallback → mark source degraded. Candidate concurrency 3, per-domain 1. **H14 rule exactly as written, never simplified for yield:** structured listing lacks website + exact identity search + official-domain search + no credible first-party site = "website not found after verification"; directory absence alone never sufficient. US-founder discovery expansion (H7).

**WS3 — Projects / Research Context.** Schema above; resolver with provenance; unknown never collapsed into false. Memory **backfill migration** (not deleted) into Settings → Profile & Defaults; old route redirects. Home: project cards ("HVAC Outreach · 86 prospects · 3 Watches active", "+ New Project") + composer; in-project quick actions (Find more / Check new signals / View list / Create Watch). "Find 50 more from the Recruiters ICP" resolves against the durable ICP object. Results server-paged (first 25, then pages/virtualized table); big jobs never held in browser state.

**WS4 — Canonical facts + freshness + contextual learning.** **Write-back split:** canonical global facts only (company.website, works_at, phone, funding_event, job_posting). Never write back why_match, fit_score, "good prospect for X", outreach angle, ranking, or thesis-specific intent relevance — those are Project/Job evaluations. Canonical Research Graph → Project/Job Evaluation → Opportunity Packet. One project's conclusions never contaminate another. **Field-level freshness:** domain/identity stable 90d; description/employment/phone/size medium 30d; job listings volatile 7d; funding/post = event timestamps; intent very volatile. Expired fact re-verifies alone — never full entity re-research.

**WS5 — Watch v2 on the job engine.** Watch = WHAT (compiled thesis) + WHEN (schedule) + CHANGE (new entity / new signal) + DELIVERY (channel). Due → create SearchJob mode="watch" (idempotent per (watch_id, scheduled_for)) → same compiler/widening/research/qualification → fingerprint diff against watch_seen_matches → only genuinely new items → notification outbox. `searchAllSources` watch path retired. Cron route (service role, all users) + vercel.json entry; manual per-user trigger unchanged.

**WS6 — Notifications.** `NotificationChannel` interface; adapters InApp, Email, SlackWebhook. **Outbox semantics:** one internal notification intent per idempotency_key — guaranteed. Downstream provider idempotency used when supported; when not supported, **no blind retry of an ambiguous external send** — status becomes `delivery_unknown`, requiring reconciliation or explicit retry. Email reuses the transport only, never outreach business logic/quotas/templates. Slack webhook encrypted, test-connection button, never in frontend state or logs. Telegram next (official bot + one-time linking code) — stretch; WebPush later.

**WS7A — Minimal deep-signal pass (REQUIRED).** Qualification split, no weakened theorems: **base eligibility** (identity/fit) → **signal research when required** (budgeted per-candidate hunt filling verified LeadSignals — fixes H8 class) → **FINAL deliverability qualification**. Signal-optional path: signal research as post-qualification enrichment. This order avoids the old circular bug (signal missing → rejected → never researched).

**WS7B — Custom signal compiler (genuinely stretch).** Signal text → observableIndicators / searchQueries / evidenceRules (zod-validated). First cut under pressure; architecture stays ready.

## Security / ownership (non-product invariant, acceptance-gated)
All user-owned tables enforce ownership/RLS: projects, project_context, project_saved_searches, project_lists, project_list_items, search_jobs, search_job_candidates, watches, watch_seen_matches, notification_connections. Server functions verify ownership. Cron/service-role code may process all due watches but never exposes service-role credentials or another user's records to a client. Notification credentials: server-only, encrypted at rest, never returned to browser, never logged. Acceptance: User A cannot read/mutate User B's project, job, list, Watch, result rows, or notification connection.

## Acceptance — mechanics deterministic, truthfulness live

**Reuse (deterministic invariants, not wall-clock):** second identical search shows canonical_cache_hits > first run, fresh_fields_reused > 0, unnecessary_live_research_calls < first run, stale_fields_researched_only. Wall-clock improvement recorded as performance metric, not correctness requirement.
**Live (procedure, not green numbers):** correct research procedure ran; every returned match evidenced; widening continued appropriately; zero/few results demonstrate coverage exhaustion honestly. No unconditional H8>0 / H14>0 / "100 complete" incentives to loosen verification. Real-web smoke tests separate.
**Whole-sequence acceptance:** Create Project → save context v1 → "find 100" → job pins snapshot v1 → first 10 stream → edit Project to v2 while running → job stays on v1 → worker restart → atomic lease reclaim → resume, no dupes → TARGET_REACHED or honest COVERAGE_EXHAUSTED → dataset lives in Project → add selected rows to a List → same thesis rerun → canonical facts reused, only stale fields re-researched, reuse invariants hold → create Watch from thesis → watch run reuses same job engine → known entity, no new signal → no notification; existing entity + NEW signal → notification; new entity → notification → ambiguous-delivery handling → no duplicate intents/sends. Plus User A/User B isolation check.
