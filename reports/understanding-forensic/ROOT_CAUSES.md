## Clarification cases required by product

- A `find plumbers in Austin`: target/location correct; current runtime decision ACT. Purpose unresolved, so desired high-value goal question is missed.
- B `find plumbers in Austin that need website services`: no redundant seller question; current route ACT. But it invents `no_website`, a separate qualification failure.
- C `find local businesses in Alberta without websites`: spec is ready; no unrelated business-model question in spec path. Legacy path has separate model-oriented clarifier, selected when spec flag is off.
- D `find investors`: frame scope question and runtime `investor_sector` question both trigger, with different wording.
- E `remote react jobs paying this much`: no amount question; false ready state and invented location `paying`.
- F `find businesses that need websites` then composer `Alberta`: new composer turn resets prior query. A panel answer can carry `location=Alberta` into SearchSpec, but frame-native state is not patched.

## UI/provider leak and browser evidence

- `activity-presenter.ts` 11-30 intentionally displays `saved leads`. `INTERNAL_RE` 53 omits OSM, OpenStreetMap, Geoapify, Foursquare, S3, DuckDB. Direct `presentActivityEvent` probes in `TRACE.jsonl` pass all those strings through action/detail. `search-browser-progress.server.ts` 57 is current adapter boundary. `result-tabs.tsx` 950 and `entity-detail-panel.tsx` 464 render raw source labels outside that adapter.
- `browser-live.server.ts` 941-960 emits a verified `row` in progress. `activity-presenter.ts` 68-80 returns only action/source/detail/count, so `search-browser-progress.server.ts` 57 drops that row before transport. `discover.tsx` 2262-2276 needs `event.row` for in-progress verified cards. This loss is proven by the producer/presenter/consumer code chain.
- `discover-welcome-hero.tsx` 4-9 and 49 stores and submits fabricated quick-chip query `find plumbers in Austin`.
- `clarify-panel.tsx` 59, 105, 150 renders one expanding inline card, vertical options, footer at bottom. No mobile height cap/internal scroll/sticky footer. No viewport reproduction was possible because no authenticated browser surface was available.
- `live-gapfill.ts` 702-705 browses only below desired verified count. `browser-live.server.ts` 12 defaults to in-process Playwright; `playwright-browser.server.ts` 43-44 launches Chromium. `scrapy-browser.tsx` 63 hides until state reports at least one visited page. Discover additionally nests the widget under the active-search panel and `browserProgressEvents.length > 0` (`discover.tsx` 2202-2281), then clears `browserProgressRun` when search ends (840-842). Browser state and progress are process-local (`scrapy-browser.server.ts` 130-137; `search-browser-progress.server.ts`). External worker functions require URL/token (`research-agent.functions.ts` 8-10), but no Discover import calls them. Production worker/env/session logs were unavailable; the exact deployed absence remains unverified.
