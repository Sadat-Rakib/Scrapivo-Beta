# Field requirement map

“Global” distinguishes the final theorem (`canonical-contract.ts:queryRequiredFields` and `evaluateQualifiedLeadTheorem`) from the separate first-page completeness gate (`completeness.ts:missingRequiredFields`). Requested fit fields can also be enforced earlier by `rowSatisfiesSpec` (`spec-search.functions.ts:362`).

| Field | All results? | Query/entity condition | Before research? | After research / failure consequence | Code |
|---|---|---|---|---|---|
| Name/title | Yes, entity name | Job also needs title | Browser seed needs title; OSM drops unnamed artifacts | Missing identity rejects | `browser-live.server.ts:~755`; `canonical-contract.ts:288` |
| Entity type | Yes, matching resolved type | Spec entity must match | `remember` excludes resolved wrong kinds | `ENTITY_TYPE_MISMATCH` | `browser-live.server.ts:~450`; `canonical-contract.ts:~330` |
| Stable `entity_id` | Yes | All entities | Provisional source allowed in browser memory | `PROVISIONAL_ENTITY` / `ENTITY_UNRESOLVED`; UI projection repeats gate | `canonical-contract.ts:~306`; `qualified-lead.ts:~164` |
| `entity_resolved` / identity confidence | Yes; confidence must not be below 0.7 if set | All | Partial can be researched | `ENTITY_UNRESOLVED` | `canonical-contract.ts:~315`; `browser-research.ts` |
| Role | No static theorem field | If stated, person `rowSatisfiesSpec`; person gate checks supported current role | Missing stated role can filter DB/live post-browser; browser attempts research | Role mismatch or `EMPLOYMENT_UNPROVEN`/`CURRENTNESS_MISMATCH` | `spec-search.functions.ts:~365`; `person-qualify.ts` |
| Company / current relationship | Not for all entities | Person founder/role claims need associated current organization | Missing relation can remain browser partial | Person gate can reject `ASSOCIATED_COMPANY_UNRESOLVED`/`EMPLOYMENT_UNPROVEN` | `person-employment.ts`; `person-qualify.ts` |
| Location | Only when Spec states location | All applicable entity types | `rowSatisfiesSpec` can filter missing/mismatched location | Theorem `MISSING_QUERY_REQUIRED` or `LOCATION_MISMATCH` | `spec-search.functions.ts:362`; `canonical-contract.ts:168,~350` |
| Industry/category | No global theorem field | Stated industry/category is enforced by coarse filter; person gate/evidence may add fit checks | **Yes**, on DB and post-browser live rows | `rowSatisfiesSpec=false` before general live enrichment | `spec-search.functions.ts:362`; `companyCategoryMatches`/`craftMatches` |
| Website URL | No universal website requirement | Company/business completeness accepts site **or** contact; no-site Spec requires absence and rejects discovered site | No-site seeds require null site; other partial seeds may lack it | Missing site may leave row incomplete; found site invalidates no-site claim | `completeness.ts:29`; `live-gapfill.ts:~695`; `qualify.ts:141` |
| Profile URL | No universal profile requirement | Person completeness accepts profile URL **or** email/phone; browser seeks a profile if absent | May be missing in partial browser candidate | Without any channel/profile, incomplete; person identity may still fail separately | `completeness.ts:29`; `browser-research.ts:~25` |
| Email | No | Only explicit “with/required email” or `require_email=true` is theorem-required | May be absent; contact harvest later if site | Explicit requirement → `MISSING_QUERY_REQUIRED`; otherwise null retained, subject to contact/site completeness | `canonical-contract.ts:168`; `completeness.ts:29` |
| Phone | No | Only explicit “with/requires/must have phone” or `require_phone=true` | May be absent | Explicit requirement → `MISSING_QUERY_REQUIRED`; otherwise null retained | `canonical-contract.ts:168`; `completeness.ts:29` |
| Contact page URL | No theorem requirement | Raw query matching “public contact details” makes browser continue if no email/phone/contact page | May be absent | Missing page alone does not reject; observed page is stored on `SpecRow`/QualifiedLead fields | `browser-research.ts:~16`; `browser-live.server.ts:~635`; `qualified-lead.ts:~338` |
| Signal / claim | No for plain directory request | Required when `spec.signal_required`; no-site/topic have explicit gates | Partial row may lack signal and enter browser research | No aligned subject-bound claim → `NO_CLAIM_EVIDENCE` etc. | `canonical-contract.ts:198,~413`; `qualify.ts:~141-164`; `verification.ts` |
| Buying intent | No global requirement | Only if SearchSpec signal/claim semantics require it; B's “may need help” is not explicit buying intent | Not a browser seed prerequisite | Cannot be invented; signal gate only when required | `search-spec.ts`; `claim-binding.ts`; `canonical-contract.ts` |
| Evidence | Not universally required by theorem | Required for signal; bounded subject-bound no-site evidence; requested content-topic evidence | Browser/source can carry provisional evidence | Missing required proof rejects; ordinary directory rows can qualify without claim evidence | `evidence.ts`; `qualify.ts:~138-164`; `canonical-contract.ts:~413` |
| `why_match` | No independent hard theorem field | Signal path derives from evidence; non-signal path derives template after qualification | Can be null in partial row | Null alone does not cause theorem rejection; evidence/identity gates can | `qualify.ts:~275`; `live-gapfill.ts:328,405` |
| Source URL | Provenance is important, not universally theorem-required | Job needs apply **or** source URL; no-site evidence needs structured source; UI links to source | Browser seed usually needs source/destination URL or resolved location | Missing required provenance prevents specific proof; generic non-signal entity may still qualify | `browser-live.server.ts:~755`; `canonical-contract.ts:~400`; `qualified-lead-view.ts:~320` |
| Official destination URL | Not a single global theorem field | Job apply/source required; other types rely on contact/site completeness and identity | Browser resolves after identity | Missing destination can keep row incomplete or less useful; publisher URL cannot be promoted as website | `spec-search.functions.ts:177`; `completeness.ts`; `site-url.ts` |

For A, “phone numbers and emails **when available**” does not make every row's email/phone a theorem requirement. For B, no direct email is requested. For C, the browser seeks public contact details, but the final query-required-field list does not require a contact page or direct email/phone.
